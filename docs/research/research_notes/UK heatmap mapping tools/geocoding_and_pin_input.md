# Geocoding, postcode lookup and address search for placing a property pin; what a Rightmove listing legitimately exposes (as of 10 October 2026)

Scope note: UK only. Research was done from public documentation, vendor pages, news and third-party technical write-ups. No Rightmove listing page was fetched or scraped for this note; statements about Rightmove page internals come from published third-party sources and are labelled as such. Anything dated before 2025 is marked "(older)".

## Key Question 1: Best free path from "postcode" to a map pin, and from "full address" to a precise building coordinate, with licence terms allowing commercial use

### Takeaway
Postcode to pin: postcodes.io (MIT software, no key, ONSPD/OS Open Names data under OGL, self-hostable via Docker) returns a postcode-unit centroid as lat/long plus OSGB eastings/northings and admin areas; it is free for commercial use for GB postcodes, with Northern Ireland (BT) postcodes carrying a separate non-OGL licence. Full address to building coordinate: there is no fully free *address-text* to coordinate source; OS Open UPRN gives free (OGL-style "free to use for everyone") per-property coordinates keyed on UPRN only, so you still need something that converts an address to a UPRN (OS Places API on the Premium plan with its £1,000/month free allowance, or a PAF-licensed vendor such as Ideal Postcodes at roughly 3-4.5p per lookup). EPC open data gives a free address->UPRN bridge, but its address fields are explicitly excluded from OGL and restricted to energy-performance-related purposes.

### Cited Findings

Postcodes.io
- postcodes.io describes itself as a "free, open-source postcode lookup API and geocoder for the United Kingdom" and states "No authentication is required to use this API." — [postcodes.io docs overview](https://postcodes.io/docs/overview)
- Software is MIT licensed: "MIT licensed. Maintained and freely available on GitHub." and "Fork it, make a contribution or even set up your own." — [postcodes.io](https://postcodes.io/)
- Data sources: "Postcodes.io serves the ONS Postcode Directory, Ordnance Survey Open Names and Scottish Postcode Directory datasets." Self-hosting via Docker: "Self Hosting: Docker containers" with `docker-compose up`. — [GitHub ideal-postcodes/postcodes.io](https://github.com/ideal-postcodes/postcodes.io)
- Update cadence as loaded on 10 Oct 2026: ONSPD "Updated quarterly (February, May, August, November)", currently August 2026; OS Open Names currently July 2026; Scottish Postcode Directory "Updated twice a year", currently 2026/2. — [postcodes.io docs overview](https://postcodes.io/docs/overview)
- Fields returned by postcode lookup (from the example response): `postcode, incode, outcode, eastings, northings, longitude, latitude, quality, country, region, european_electoral_region, admin_district, admin_county, admin_ward, parish, bua, national_park, ttwa, nuts, lsoa, msoa, lsoa11, msoa11, lsoa21, msoa21, oa21, index_of_multiple_deprivation, ruc11, ruc21, parliamentary_constituency, parliamentary_constituency_2024, senedd_constituency, ced, nhs_ha, nhs_region, primary_care_trust, ccg, icb, cancer_alliance, pfa, lep1, lep2, date_of_introduction, date_of_termination`, plus a `codes` object of GSS identifiers. A 404 for a terminated postcode still returns `terminated` with longitude/latitude. — [postcodes.io postcode lookup docs](https://postcodes.io/docs/postcode/lookup)
- Rate limits: not stated anywhere on the official docs pages I fetched; a third-party aggregator says "unlimited usage subject to its fair use policy" and "specific numerical limits are not publicly documented". — [apispine.com (third party)](https://apispine.com/postcodesio); official pages silent: [postcodes.io docs overview](https://postcodes.io/docs/overview)
- ONSPD licence: ONS says "Our postcode products (derived from Code-Point® Open) are subject to the Open Government Licence" with required attributions including "Contains OS data © Crown copyright and database right [year]"; but for Northern Ireland "BT" postcodes "you need a separate licence for commercial use direct from Land and Property Services" and ONS "only issue a Northern Ireland End User Licence (for internal business use only)". — [ONS geography licences](https://www.ons.gov.uk/methodology/geography/licences); summarised also in [Ideal Postcodes ONSPD licensing guide](https://ideal-postcodes.co.uk/guides/onspd-licensing)

OS Names API (free, OpenData plan)
- OS Names API is listed under "OS OpenData Plan (FREE)", "Premium Plan" and "Public Sector Plan", is "Free to use for everyone", covers "nearly 44,000 individual settlements over 870,000 named and numbered roads and 1.7 million postcodes", and "won't return a specific address in detail, or perform bulk searches" (OS recommends AddressBase / OS Places API for addresses). — [OS Names API product page](https://www.ordnancesurvey.co.uk/products/os-names-api)
- Docs: "Free for all to use for any purpose", data from OS Open Names "available under the Open Government Licence attribution"; you can "Search for postcodes" but cannot "Search for specific addresses"; GeoJSON/XML, GB coverage. — [docs.os.uk OS Names API](https://docs.os.uk/os-apis/accessing-os-apis/os-names-api)

OS Open UPRN and Open Linked Identifiers (free, but no address text)
- OS Open UPRN "contains the position of each record held within AddressBase Premium along with the unique identifier"; CSV and GeoPackage with five attributes: `UPRN, X_COORDINATE, Y_COORDINATE, LATITUDE, LONGITUDE`; "All UPRNs will be included, independent of their lifecycle state" (under construction, in use, demolished). No address text. — [docs.os.uk OS Open UPRN overview](https://docs.os.uk/os-downloads/identifiers/os-open-uprn/os-open-uprn-overview)
- Product page: "Free to use for everyone", "updated every six weeks", UPRNs "assigned to approximately 40 million addressable locations". — [OS Open UPRN product page](https://www.ordnancesurvey.co.uk/products/os-open-uprn)
- OS Open Linked Identifiers holds "the authoritative relationships between Unique Property Reference Numbers (UPRNs), Unique Street Reference Numbers (USRNs) and Topographic Object Identifiers (TOIDs)" (links address to building footprint/street), updated every six weeks; the OS Linked Identifiers API is "free under the OS OpenData Plan". — [OS Open Linked Identifiers](https://ordnancesurvey.co.uk/products/os-open-linked-identifiers); [OS Linked Identifiers API](https://www.ordnancesurvey.co.uk/products/os-linked-identifiers-api)
- Ideal Postcodes' blog states OS Open UPRN lacks address text so you need another source for it. — [Ideal Postcodes blog: Not all UPRN data is the same](https://blog.ideal-postcodes.co.uk/not-all-uprn-data-is-the-same)

EPC open data as a free address->UPRN bridge (England & Wales)
- MHCLG's bulk EPC service offers "bulk certificate data in CSV format" and "a developer API"; requires GOV.UK One Login; covers England and Wales certificates since 2012; "All content is available under the Open Government Licence v3.0, except where otherwise stated". — [get-energy-performance-data.communities.gov.uk](https://get-energy-performance-data.communities.gov.uk/)
- Licensing restrictions page: OGL applies to "All data fields other than the address and postcode data" and this "includes Ordnance Survey UPRNs". The address1/2/3/postcode fields were "processed against Ordnance Survey's Address Base Premium product" incorporating Royal Mail PAF; OS and Royal Mail "reserve all their respective copyright, database rights"; address data may be used "solely for specific purposes related to the energy performance of buildings" (listed purposes include "Supporting property market transparency"); "Any use of address data which is not specified in this notice" requires "an appropriate licence from Ordnance Survey"; non-compliance "may lead to Ordnance Survey and/or Royal Mail Group Limited taking legal action". — [EPC licensing restrictions](https://get-energy-performance-data.communities.gov.uk/guidance/licensing-restrictions)
- UPRNs were appended to EPC bulk data from November 2021 and by mid-2022 "97.8%" of records had a UPRN (older, 2022). — [UKAuthority](https://www.ukauthority.com/articles/uprns-combine-with-epcs-for-energy-efficiency/); [OS blog on EPC UPRN release](https://ordnancesurvey.co.uk/blog/ordnance-survey-open-identifiers-uprn-epc-data-release)

OpenStreetMap-based options (Nominatim, Photon, Pelias)
- Nominatim public server policy: "No heavy uses (an absolute maximum of 1 request per second)"; must "Provide a valid HTTP Referer or User-Agent identifying the application"; autocomplete: "you must not implement such a service on the client side using the API"; bulk geocoding "not encouraged"; services whose main function is geocoding must run their own instance; for larger needs "you can install your own instance of Nominatim". The policy covers only nominatim.openstreetmap.org. — [OSMF Nominatim usage policy](https://operations.osmfoundation.org/policies/nominatim/)

- Pelias is MIT licensed, Elasticsearch-based, multi-source (OSM, WhosOnFirst, OpenAddresses, GeoNames); OSM importer accepts any Geofabrik pbf extract (a GB extract exists). — [sumguy.com comparison (third party)](https://sumguy.com/nominatim-vs-photon-vs-pelias/); [Mobilizon geocoder docs](https://docs.joinMobilizon.org/administration/configure/geocoders/)
- UK OSM address coverage is weak: a 2020 Talk-GB post (older) said "in most areas housenumber coverage is abysmal... the UK has about 1.6 million [housenumbers] as of 2018" versus 14 million in Germany; an OSM community thread notes "there is no open source of addresses in the UK outside of OSM". A UK Quarterly Project for Q2 2026 focuses on addresses. — [Talk-GB Dec 2020](https://lists.openstreetmap.org/pipermail/talk-gb/2020-December/025793.html); [OSM community: UK house numbers](https://community.openstreetmap.org/t/uk-house-numbers/103266); [OSM wiki UK Q2 2026 project](https://wiki.openstreetmap.org/wiki/UK_Quarterly_Project/2026/2026_Q2_Project:_Addresses)

Accuracy: postcode centroid vs building
- postcodes.io returns one lat/long per postcode unit; the docs do not state what the point represents (the field `quality` appears in the response but is undocumented on the lookup page). — [postcodes.io postcode lookup docs](https://postcodes.io/docs/postcode/lookup)
- OS Places API returns per-property `X_COORDINATE/Y_COORDINATE` (BNG metres) and `LNG/LAT`, plus `RPC` which "describes the accuracy of the coordinate that has been allocated to the BLPU"; the LPI `POSTCODE_LOCATOR` is "based purely on a spatial match against Code-Point® with polygons" and "must be used in conjunction with the RPC field". — [docs.os.uk OS Places API datasets](https://docs.os.uk/os-apis/accessing-os-apis/os-places-api/datasets)

### Inferences
- For a startup, the cheapest compliant stack is: postcodes.io (self-hosted or public) for postcode->centroid pin; OS Names API (OpenData plan) for free place/road/postcode typeahead that is not address-level; and either OS Places API (Premium plan, within the £1,000/month free allowance) or Ideal Postcodes (~3-4.5p/lookup, 50 free trial credits) for full address -> UPRN -> rooftop coordinate. All of these permit commercial use for GB postcodes; the only free-tier that excludes commercial use is MapTiler's free plan.
- A free address-level coordinate pipeline (EPC address -> UPRN -> OS Open UPRN lat/long) is technically feasible but the EPC address fields are not OGL and are limited to energy-performance purposes; a property-acquisition analysis tool would probably fall under "Supporting property market transparency" only arguably, so this should be treated as a legal risk and checked with OS before use.
- OSM-based geocoders (Nominatim/Photon/Pelias) are a poor fit for UK house-number geocoding because UK OSM address coverage is sparse; they remain fine for town/street/postcode-level lookups and the public Nominatim server must not be used for autocomplete.
- Postcode centroid accuracy is inherently limited to the postcode unit (typically a street segment of ~15 addresses in urban areas); the pin will be on the right street but not the right building. A "house number + postcode" input with an OS Places or Ideal Postcodes lookup moves the pin to the building.

### Gaps
- postcodes.io publishes no numeric rate limit or formal fair-use policy on its docs; the "quality" field and whether lat/long is the ONSPD centroid are not documented on the lookup page (ONSPD itself defines them, but I did not fetch the ONSPD user guide).
- OS does not state on the OS Open UPRN docs or product page which licence applies ("Free to use for everyone" only); the OS OpenData licence (OGL-compatible) is the likely answer but was not verified on an OS licensing page.
- Exact per-transaction price for OS Places API was not found (osdatahub.os.uk pages render client-side and returned only the title); see Key Question 2.
- Whether Ideal Postcodes' terms allow storing/caching returned coordinates and addresses long-term was not checked.
- Loqate's figures are from search snippets of its pricing pages, not the full page text.

## Key Question 2: Does the OS Data Hub OpenData plan include OS Names API? Does OS Places API require Premium, and what does the free Premium allowance cover?

### Takeaway
Yes: OS Names API is explicitly on the "OS OpenData Plan (FREE)" and is free for any purpose. OS Places API is listed only under the Premium Plan and Public Sector Plan; the Premium plan gives "free premium data (API transactions) up to £1,000 per month" and automatic access to all OpenData, but I could not retrieve a current per-transaction price for OS Places from OS's pages, so the number of free address lookups the £1,000 buys is a gap.

### Cited Findings
- OS Names API plans: "OS OpenData Plan (FREE)", "Premium Plan", "Public Sector Plan"; "Free to use for everyone". — [OS Names API product page](https://www.ordnancesurvey.co.uk/products/os-names-api)
- OS Names API docs: "Free for all to use for any purpose"; data from OS Open Names under the Open Government Licence. — [docs.os.uk OS Names API](https://docs.os.uk/os-apis/accessing-os-apis/os-names-api)
- OS Places API plans listed: "Public Sector Plan" and "Premium Plan" only; "Search by postcode, UPRN, full or partial address"; "find the complete address including its location"; data from "AddressBase Premium and AddressBase Premium Islands"; updated daily; GeoJSON/XML. — [OS Places API product page](https://www.ordnancesurvey.co.uk/products/os-places-api)
- OS Places API docs: coverage "United Kingdom, Jersey, Guernsey and the Isle of Man"; Jersey/Guernsey coordinates are "0.0"; you cannot "Carry out bulk queries" and transactions are "subject to API throttling"; `dataset` parameter selects "DPA or LPI". — [docs.os.uk OS Places API](https://docs.os.uk/os-apis/accessing-os-apis/os-places-api)
- OS Places request types: Find ("Return matched addresses based on a free text search"), Postcode, UPRN, Nearest, BBOX, Radius, Polygon. — [docs.os.uk OS Places technical specification](https://docs.os.uk/os-apis/accessing-os-apis/os-places-api/technical-specification)
- DPA is an address "Ordnance Survey has matched against a Royal Mail PAF (Postcode Address File) address"; LPI is "a structured text entry that identifies a Basic Land and Property Unit (BLPU)" and "does not need to receive deliveries from the Royal Mail to exist". Find returns `MATCH` 0-1 with `MATCH_DESCRIPTION` Exact 1.0 / Good 0.8-0.9 / Partial 0.7 / No Match <0.7; both datasets return `UPRN, ADDRESS, X_COORDINATE, Y_COORDINATE, LNG, LAT, CLASSIFICATION_CODE, RPC, STATUS`; DPA returns `POSTCODE`, LPI returns `POSTCODE_LOCATOR`. — [docs.os.uk OS Places API datasets](https://docs.os.uk/os-apis/accessing-os-apis/os-places-api/datasets)
- OS Data Hub plans: OpenData plan "free and unlimited usage but with a data limit determined by the detail"; Premium plan gives "free premium data (API transactions) up to £1,000 per month" and "If you sign up to the Premium plan, you'll automatically be able to access all of our free OS OpenData too"; Public Sector plan "exclusive to members of the Public Sector Geospatial Agreement" with free unlimited OpenData and premium data; projects can run in development and live mode. — [OS: What is the OS Data Hub?](https://www.ordnancesurvey.co.uk/developers/os-data-hub)
- (older, 2020) At launch, The Register reported: "Burn through that £1,000, however, the OS will expect to be paid for its premium wares." — [The Register, 1 Jul 2020](https://www.theregister.com/2020/07/01/os_data_hub/)
- A UK government (MoJ) engineering guide notes OS Places is free to public sector bodies under the PSGA. — [MoJ Operations Engineering user guide](https://user-guide.operations-engineering.service.justice.gov.uk/documentation/services/osdatahubapi.html)

### Inferences
- A startup should register for the Premium plan (free to join) to get OS Places plus all OpenData APIs under one key; a single-listing, user-driven flow would make a handful of Places calls per user session and is very likely to stay inside the £1,000/month allowance.
- The OS Places `Find` endpoint with its `MATCH` score is the natural backend for "user types house number + postcode -> confirm address -> drop pin"; the `Postcode` endpoint returns all addresses in a postcode for a pick-list UX.

### Gaps
- Current per-transaction prices for OS Places API (and therefore how many lookups £1,000 covers) were not retrievable: osdatahub.os.uk/plans, /support/plans and /support/faqs all rendered only the page title via fetch. The OS page says pricing and the definition of a transaction are published on the Data Hub.
- OS API terms about whether addresses/coordinates returned by OS Places may be stored or displayed to end users in a commercial app were not retrieved (OS's product page says nothing about display licensing).

## Key Question 3: What exactly does a Rightmove page expose (address granularity, postcode granularity, floor area), and what do Rightmove's current terms permit for a user analysing a single listing in their own browser?

### Takeaway
Third-party technical sources consistently report that a Rightmove property page at `/properties/{numeric id}` embeds a `PAGE_MODEL` JavaScript object whose `propertyData` includes `address.displayAddress` (street-level), `address.outcode` and `address.incode` (the incode "where published", so the full postcode is often but not always present), `location.latitude/longitude`, price, bedrooms/bathrooms, property sub-type, floorplans, EPC image URL, a displayed size string and sometimes numeric floor area; the listing ID in the URL reveals nothing by itself. Rightmove's Terms of Use (Last Updated February 2026) prohibit "bots, crawlers, scrapers or other automated programs or means to access or collect data", bar extracting information "other than by means of direct human interaction", restrict access to a browser or Rightmove's own app, require written consent for links from any "extension, plug in, or computer program", and limit copying/reproduction of material; the terms do not expressly address a user reading a single page in their own browser and manually re-typing facts into another tool.

- I found no reported UK court case between Rightmove and a scraper or extension developer in 2023-2026; vendor FAQs discuss generic risks (terms breach, copyright in photos/descriptions, Computer Misuse Act, GDPR) without naming cases. — [webscraping.ai FAQ (vendor, partly "as of early 2023")](https://webscraping.ai/faq/rightmove-scraping/what-is-the-risk-of-litigation-when-scraping-rightmove-data)

### Inferences
- Granularity: the displayed address is street-level ("displayAddress"); the full postcode is frequently present via outcode+incode in the page model but is agent-controlled and sometimes missing, so a pin from the page alone can be anywhere from building-level (lat/long present) to outcode-level. Floor area is present only when the agent supplies it (a `displaySize` string or numeric sq ft/sq m), typically alongside a floorplan; the EPC is exposed as an image link, not structured data.
- The URL `/properties/{id}` contains only Rightmove's internal listing ID; nothing about the address is derivable from it without loading the page.
- The February 2026 terms are drafted broadly enough that any tool (extension, bookmarklet, server-side fetch) that reads page data on a user's behalf is "technical means" and not "direct human interaction"; a server-side fetch of a listing URL pasted by the user would clearly breach cl. 5.2/5.5. A user manually reading the page and typing price/address/size into a separate app is the only path the terms do not restrict, and that is the position the prompt's "user types postcode + house number + asking price" fallback occupies.
- Because cl. 13.4 restricts even linking from extensions without consent, an in-browser extension that annotates Rightmove pages sits in a grey area regardless of whether it extracts data.

### Gaps
- No Rightmove-authored documentation of the page model exists publicly; all structure claims are third-party and subject to change without notice.
- Whether Rightmove pages carry schema.org JSON-LD could not be confirmed from public sources without fetching a listing page (deliberately not done).
- No evidence found of Rightmove enforcement action (legal or technical) specifically targeting single-user browser extensions, as opposed to scrapers; absence of evidence here is not evidence of absence.

## Key Question 4: How do Property Log and similar extensions position themselves legally, and have they been blocked?

### Takeaway
Property Log (Chrome only, launched 2018 by an anonymous Didcot developer, ~100,000 users per a third-party auditor) presents itself only as "in no way affiliated with Rightmove", crowdsources price changes from users ("submit ones you've found to us!") and charges heavy users £2.99/month; PaTMa Property Insights (v2.12.0, July 2026, 10K+ users) offers free price history on Rightmove, Zoopla, OnTheMarket, PropertyNews and PropertyPal with addresses behind a subscription and has shipped repeated updates "to support a change in Rightmove". I found no public evidence that Rightmove has legally or technically blocked either extension; the only "removed" signal is a third-party auditor snapshot of Property Log (v1.6.4, Jan 2024) whose cause is unstated, while the developer's site is live with a 2026 copyright. Neither publishes a legal rationale beyond the non-affiliation disclaimer.

### Inferences
- These tools survive on a crowdsourced model: each user's browser reads the listing they are already viewing and reports the price to a central database, so the operator never scrapes Rightmove server-side. ## Key Question 5 (supporting): The user-side alternative and fallback UX

### Takeaway
The lowest-risk flow is for the user to type the postcode (free centroid pin via postcodes.io), optionally a house number/name (resolved to a UPRN and rooftop coordinate via OS Places Find/Postcode endpoints or Ideal Postcodes autocomplete), and the asking price, bedrooms and floor area by hand; this avoids touching Rightmove entirely and uses only OGL/commercially licensed data. Address-autocomplete UX is free with OS Names (places, roads, postcodes, not addresses), free-as-you-type with Ideal Postcodes (billed only on selection), and session-priced with Google/Mapbox.

### Cited Findings
- Ideal Postcodes: "Searching as a customer types is free" and each UK lookup returns UPRN and rooftop coordinates. — [Ideal Postcodes pricing](https://ideal-postcodes.co.uk/pricing)
- OS Places `Postcode` request returns "matched addresses based on a property's postcode" (a pick-list of every address in the postcode); `Find` returns matches with a 0-1 `MATCH` score. — [docs.os.uk OS Places technical specification](https://docs.os.uk/os-apis/accessing-os-apis/os-places-api/technical-specification); [datasets page](https://docs.os.uk/os-apis/accessing-os-apis/os-places-api/datasets)
- OS Names API supports place, road and postcode search but "won't return a specific address in detail". — [OS Names API product page](https://www.ordnancesurvey.co.uk/products/os-names-api)
- Google Autocomplete is session-based: a session ending in a Place Details Pro/Enterprise call makes the autocomplete requests free ("Autocomplete Session Usage" unlimited free), otherwise Autocomplete Requests bill at $2.83/1,000 after 10,000 free. — [Google Maps Platform pricing](https://developers.google.com/maps/billing-and-pricing/pricing); [Woosmap explainer (third party)](https://www.woosmap.com/blog/google-places-api-pricing)
- Mapbox Address Autofill: 0-1,000 sessions free then $12.50/1,000; Search Box sessions 0-2,500 free then $11.50/1,000. — [Mapbox pricing](https://www.mapbox.com/pricing)
- Public Nominatim forbids client-side autocomplete. — [OSMF Nominatim usage policy](https://operations.osmfoundation.org/policies/nominatim/)
- PaTMa charges for the "property address" feature while price history is free, i.e. address identification is treated as the premium, data-licensed step. — [ChromeBoard: PaTMa Property Insights](https://chromeboard.com/extension/patma-property-insights-gbppndfkbhfpmpidebmnhkofloklojii)

### Inferences
- A practical two-tier UX: (1) postcode-only -> centroid pin with a visible "approximate" radius; (2) postcode + house number -> OS Places/Ideal Postcodes confirmation list -> exact building pin, showing the UPRN for later joins (EPC floor area, Land Registry price paid). Price, bedrooms and floor area are typed by the user, with the Rightmove page open in another tab as their reference, which is the only use the Rightmove terms clearly leave untouched.
- If the product must stay fully free, limit precision to postcode centroid (postcodes.io) and treat house-number precision as the first paid dependency (OS Places within the £1,000 allowance is effectively free at single-listing volumes).

### Gaps
- No published source describes the fallback UX used by comparable UK property-analysis tools beyond the PaTMa free/paid split noted above.
